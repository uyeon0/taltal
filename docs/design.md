# 디자인 기준

색, 서체, 간격, 컴포넌트 상태, 그림, 재료 배분 표현, 양 표기를 정한다. 토큰 값은 `docs/tokens.css`에 있고, 화면 구성과 동작은 `docs/requirements/`를 따른다.

## 디자인 방향

- 정돈된 정보 구조 위에 선명한 주황 면, 먹색 선, 재료 펜 일러스트, 다람쥐 캐릭터로 개성을 만든다.
- 큰 제목은 곡선이 있는 묵직한 한글 서체를 쓰고, 본문, 수량, UI는 명료한 산세리프를 쓴다.
- 그림은 제품의 개성을 만드는 요소다. 화면마다 역할에 맞는 그림을 두되, 다음 행동 버튼이 화면 밖으로 밀리지 않게 한다.
- 장식색이나 도형을 더해 채우지 않는다. 브랜드 인상은 색 면, 먹색 윤곽, 서체, 그림의 관계로 만든다.

## 색

### 기본색

| 토큰 | HEX | 역할 |
| --- | --- | --- |
| `brand.primary` | `#F59A4F` | 브랜드 주황, 강조 면 |
| `neutral.light` | `#FAFAF7` | 밝은 배경, 카드, 입력 면 |
| `neutral.ink` | `#20211E` | 기본 글자, 주요 경계, 반전 버튼 |
| `text.muted` | `#5F625A` | 밝은 면의 부가 설명, 단위 |
| `border.subtle` | `#CFD1C9` | 밝은 면의 장식 구분선 |
| `border.strong` | `#20211E` | 입력칸, 주요 카드의 경계 |
| `action.hover-pressed` | `#234386` | 버튼 hover, pressed |
| `action.on-hover-pressed` | `#FFFFFF` | 블루 반응 배경 위 글자 |

- 화면 배경은 주황이다. 소개, 시작 홈, 재료 입력, 추천 결과와 계산 중, 오류, 추천 없음 상태가 모두 같다.
- 주황 배경 위에서는 Light 카드로 정보와 입력 영역을 나눈다.
- 바텀시트는 Light 면이다. 화면 위에 겹치는 층이라 주황 바탕과 구분한다.
- 입력칸은 Light를 쓴다.
- 주황 면의 글자는 부가 글자까지 Ink를 쓴다. Muted는 밝은 면에서만 쓴다.
- 핵심 수량, 오류 설명, 판단에 필요한 정보를 Muted로 약하게 만들지 않는다.
- Subtle 선은 장식 구분에만 쓴다. 입력, 선택, 포커스를 표시하는 수단으로 쓰지 않는다.
- 브랜드 Secondary 색은 없다. 블루는 액션 반응과 Info 상태에 쓴다.

### 버튼

| 종류 | 평소 | hover, pressed | 쓰는 곳 |
| --- | --- | --- | --- |
| 주요 | Primary 면, Ink 글자, Ink 선 | `#234386` 면, White 글자, Ink 선 | 밝은 면 |
| 주요 | Ink 면, Light 글자, Ink 선 | `#234386` 면, White 글자, Ink 선 | 주황 면 |
| Secondary | Light 면, Ink 글자, Ink 선 | `#234386` 면, White 글자, Ink 선 | 밝은 면과 주황 면 |
| Ghost | 아이콘 + Ink 글자, 면과 선 없음 | 아이콘과 글자가 블루 | 밝은 면의 가장 낮은 행동 |
| Ghost | 아이콘 + Ink 글자, 면과 선 없음 | Ink 유지, 글자에 밑줄 | 주황 면의 가장 낮은 행동 |

- 주요 버튼 두 종류는 배경에 따라 색만 반전한 같은 우선순위다. 색은 버튼 바로 아래 면을 따른다. 주황 바탕 위 Light 카드 안의 주요 버튼은 Primary 면이다.
- 직접 입력, 재료 추가처럼 주 흐름을 돕는 보조 행동은 Ghost로 둔다.
- 모바일에서는 hover 없이도 동작해야 한다. hover 색은 마우스처럼 정밀한 포인터에서만 보여 준다. 손가락으로 누른 버튼이 hover 색으로 남지 않게 하려는 것이다.
- Ghost는 아이콘을 빼지 않는다. 평소 모습만으로 누를 수 있다는 것을 알려야 한다.
- 모든 버튼의 터치 영역은 44px 이상이다.

### 상태색

| 토큰 | HEX | 적용 |
| --- | --- | --- |
| `status.success` | `#236744` | 성공 아이콘, 강조선 |
| `status.warning` | `#805900` | 주의 아이콘, 강조선 |
| `status.error` | `#B3362D` | 오류 아이콘, 강조선, 입력 경계, 오류 문구 |
| `status.info` | `#234386` | 정보 아이콘, 강조선 |

- 상태 메시지의 바탕은 Light, 제목, 본문, 기본 외곽선은 Ink로 둔다.
- 상태색은 아이콘과 한쪽 강조선에만 쓰고, 아이콘 형태와 문구를 함께 제공한다.
- 상태별 파스텔 배경을 만들지 않는다.
- 오류 입력은 Light 바탕, Ink 입력값, Error 경계와 오류 설명을 쓴다. `aria-invalid`, `aria-describedby`로 입력과 설명을 연결한다.

## 서체

| 역할 | 서체 | 크기, 굵기 |
| --- | --- | --- |
| 브랜드 큰 제목 | 낭만있구미체 | 28~36px, 400. 기본 32px |
| 고정된 짧은 제목 | 낭만있구미체 | 20~24px, 400 |
| 기능 제목, 동적 요리명 | SUIT | 20~24px, 600~700 |
| 본문 | SUIT | 16px 이상, 400~500 |
| UI 항목명 | SUIT | 16px 이상, 600 |
| 입력값 | SUIT | 16px 이상, 400~600 |
| 주요 버튼 | SUIT | 16px 이상, 600~700 |
| 핵심 수량, 남는 양 | SUIT | 16px 이상. 강조는 20px, 600. 결과 요약 수치는 24px, 700 |
| 라벨 태그(결과 요약의 "다 써요", "남아요", 요리 카드의 "N번째 요리") | SUIT | 14px, 700 |
| 부가 정보 이름(요리 카드의 "있으면 좋음", "필요한 양념") | SUIT | 14px, 700 |
| 오류 설명 | SUIT | 16px 이상 |
| 부가 설명, 단위 | SUIT | 14px 이상, 400~500 |

- 결과 요약은 라벨 태그와 수치를 한 줄에 두고 세로 가운데로 맞춘다. 크기가 다른 글자의 기준선을 맞추면 어긋나 보이기 때문이다.
- 시작 홈 예시 카드의 요리명은 요리 3가지를 나열하는 목록 항목이라 동적 요리명 대신 UI 항목명(16px, 600)을 쓴다. 카드 제목은 재료 줄(20px, 700)이다.
- 낭만있구미체는 `font-display`로만 쓴다. `font-heading`은 SUIT다. shadcn 카드 제목에 동적 요리명이 들어가기 때문이다.
- 낭만있구미체는 고정 문구에만 쓴다. 요리명, 재료명, 사용자 입력에는 SUIT를 쓴다.
- 낭만있구미체는 한글 2,780자만 그려져 있고, 나머지 8,392자는 빈 글자로 등록돼 있다. 브라우저가 대체 글꼴로 넘기지 않아 공백으로 보이므로 `unicode-range`로 그려진 글자만 지정한다. 지원 글자 목록은 `src/_app/fonts/gumi-romance-hangul.txt`다.
- 고정 문구를 추가하면 지원 글자 목록에서 글자를 확인한다.
- 행간은 본문 1.5, 제목 1.3이다. 자간은 조정하지 않는다.
- `font-synthesis: none`으로 가짜 굵기를 만들지 않는다. 서체를 늘이거나 찌그러뜨리지 않는다.
- 글자 크기는 상대 단위로 구현하고 사용자 확대와 줄바꿈을 허용한다. 공간이 부족해도 글자를 줄이지 않는다.

### 폰트 파일

두 서체 모두 CDN 없이 셀프 호스팅하고 `next/font/local`로 불러온다. 서버에서 그리는 레시피 이미지는 woff2와 가변 글꼴의 굵기를 읽지 못하므로 `src/_app/fonts/image/`의 공식 OTF를 따로 쓴다.

| 서체 | 파일 | 이용 조건 |
| --- | --- | --- |
| SUIT | `SUIT-Variable.woff2` (100~900) | SIL OFL 1.1. `LICENSE-SUIT.txt`를 함께 둔다. 파일을 수정하면 SUIT 이름을 쓸 수 없으므로 서브셋을 만들지 않는다 |
| 낭만있구미체 | `GumiRomance-Regular.woff2` (400) | 무료, 상업 이용 가능. 유료 판매와 왜곡 변형 금지. `NOTICE-GumiRomance.md`를 함께 둔다 |
| SUIT (이미지) | `image/SUIT-Regular.otf`, `SUIT-Medium.otf`, `SUIT-SemiBold.otf`, `SUIT-Bold.otf` (400~700) | 공식 릴리스 v2.0.5의 `SUIT-otf.zip`에서 받은 그대로다. 조건은 SUIT와 같다 |
| 낭만있구미체 (이미지) | `image/GumiRomance-Regular.otf` (400) | 구미시 공식 `낭만있구미체.zip`의 `Gumi Romance.otf`를 이름만 바꿔 둔 것이다. 조건은 낭만있구미체와 같다 |

## 공간과 형태

간격은 4, 8, 12, 16, 24, 32, 48px만 쓴다. Tailwind 숫자로 1, 2, 3, 4, 6, 8, 12다.

| 쓰는 곳 | 값 | 토큰 |
| --- | --- | --- |
| 화면 좌우 | 16px | `--page-gutter` |
| 카드, 바텀시트 안쪽 | 16px | `--card-padding`, `--sheet-padding` |
| 목록 항목 사이 | 8px | `--list-gap` |
| 관련 요소 묶음 | 12px | `--group-gap` |
| 구역 사이 | 24px | `--section-gap` |
| 조작 최소 높이 | 44px | `--control-height` |
| 주 행동 버튼 높이 | 48px | `--control-height-primary` |

| 항목 | 값 |
| --- | --- |
| 입력, 버튼, 여러 개 고르는 재료 칸 라운딩 | 8px |
| 하나 고르는 선택 항목(수량, 인분, 가짓수) 라운딩 | 알약 모양(높이의 절반) |
| 카드 라운딩 | 20px |
| 결과 요약 카드 | 라운딩 없이 네 모서리를 24px씩 사선으로 깎는다 |
| 라벨 태그 | Ink 면, Light 글자, 선 없음, 알약 모양. 안쪽 위아래 4px, 좌우 12px |
| 바텀시트 위쪽 라운딩 | 20px |
| 기본 선 | 3px |
| 선택, 강조 선 | 3px |
| 장식 구분선 | 1px, Subtle |
| 포커스 | 블루 3px, 간격 2px, 투명도 없음 |
| 그림자 | 쓰지 않는다 |

- 층은 색 면과 먹색 선으로 구분한다. 바텀시트 뒤는 Ink 50% 막으로 덮는다.
- 같은 묶음에 속한 행(재료 목록, 요리 묶음)은 카드 하나에 담고 행 사이를 1px Subtle 선으로 나눈다. 행마다 3px 상자를 두지 않는다.
- 추천 결과 화면의 조건 칩 줄은 스크롤해도 위에 붙고, 아래를 앱 폭 전체의 3px Ink 선으로 나눈다. 스크롤되는 내용과 조건 칩 줄의 층을 가르려는 것이다. 조건 칩은 Secondary 버튼 모양이고, 화면 폭에서 좌우 여백을 뺀 너비를 채운다.
- 소개와 시작 홈은 제목 영역(제목, 설명, 다람쥐) 아래를 앱 폭 전체의 3px Ink 선으로 나눈다. 같은 주황 바탕에서 제목 영역과 그 아래 구역의 경계를 보이게 하려는 것이다.
- 사선으로 깎은 모서리는 결과 요약 카드만 쓴다. 요약을 다른 카드와 모양으로 구분하려는 것이다.
- 라벨 태그는 누를 수 없는 표시다. hover, pressed 모습을 두지 않는다. 선이 없고 높이가 낮아서 3px 선, 44px 높이의 선택 칩과 모양으로 구분된다.
- 콘텐츠 최대 폭은 448px이고 가운데에 둔다. 448px보다 넓으면 바깥은 Light이고, 앱 영역 좌우에 기본 선 굵기(3px)의 Ink 선을 둔다.
- breakpoint는 360px 이하 보정 하나만 쓴다(`max-compact:`).

## 컴포넌트 상태

| 상태 | 적용 |
| --- | --- |
| 비활성 | Light 면, Muted 글자, Subtle 선. 투명도로 만들지 않고, 막힌 이유를 근처 문구로 알린다 |
| 여러 개 고르는 재료 카드 | 체크. 선은 기본 선과 같은 3px Ink이고 면은 Light를 유지한다. 선 굵기로는 구분하지 않는다 |
| 하나 고르는 인분, 가짓수 | Ink 면, Light 글자, 체크 |
| 버튼 로딩 | 버튼 폭 유지, 스피너와 문구, `aria-busy`. 다시 누를 수 없다 |
| 화면 로딩 | 스피너와 바뀌는 문구 |

화면 로딩 문구는 1.2초마다 바꾸고, 응답이 빨라도 2.4초 동안 보여 준다. 사용자가 넣은 재료명을 넣은 문구와 고정 문구를 섞고, 재료명이 들어가므로 SUIT로 표시한다. 화면 읽기에는 고정 안내를 한 번만 전달한다. 동작 줄이기에서는 스피너가 멈추고 첫 문구를 유지한다.

## 그림

| 그림 | 쓰는 곳 |
| --- | --- |
| 다람쥐 | 소개 제목 영역, 시작 홈, 빈 목록, 계산 중, 결과 도입부, 추천 없음, 오류 |
| 재료 이미지 | 재료 선택 격자와 담은 재료 목록의 모든 항목, 요리 카드의 가진 재료, 소개 1장 미리 보기 |
| 그림 없음 | 수량을 고르는 영역, 사용량 막대 |

그림의 위치는 각 화면의 요구사항 문서에서 정하고, 크기는 구현하면서 화면에 맞게 정한다. 요리 카드의 재료 이미지는 담은 재료 목록과 같은 48px로 보여 준다. 같은 재료를 두 화면에서 같은 크기로 이어 보게 하려는 것이다.

원본은 기록 저장소의 1254×1254 투명 PNG다. 앱에는 `scripts/build-image-assets.mjs`가 재료 그림을 256px, 다람쥐를 640px로 줄여 `public/images/`에 넣는다. 화면에 74px, 200px 안팎으로 쓰므로 3배 밀도 화면까지 선명하다. 그림 선택이 바뀌면 스크립트를 다시 실행한다.

### 공유 이미지

링크를 공유할 때 미리보기로 쓰는 1200×630 PNG다. 주황 바탕에 왼쪽에는 서비스 이름과 한 줄 설명을, 오른쪽에는 다람쥐(`mascot.default`)를 둔다. 서비스 이름은 낭만있구미체, 설명은 SUIT 600이고 색은 Ink다. 화면보다 크게 그리므로 간격과 글자 크기는 이 이미지에서 따로 정하고, 장식색과 도형은 더하지 않는다. 서버가 빌드할 때 그린다.

### 재료 이미지

- 식재료를 채움, 명암, 그라데이션 없이 검정 펜선으로 그린다.
- 선 끝은 둥글고 굵기와 곡선은 약간 불규칙하다.
- 주황 면과 Light 면 양쪽에서 읽혀야 한다.
- 이미지와 재료 이름을 함께 표시한다. 그림 없이도 이름, 수량, 상태를 이해할 수 있어야 한다.
- 비슷한 재료는 그림 하나를 함께 쓸 수 있다. 이때도 재료 ID와 이름은 합치지 않는다.
- 그림이 없는 재료와 이미지를 불러오지 못한 재료에는 공통 대체 그림(접힌 종이봉투)을 쓴다. 이름, 수량, 선택 동작은 그대로 유지한다.
- 인접한 글자가 재료명을 제공하므로 이미지의 대체 텍스트는 비운다.

### 다람쥐

캐릭터는 다람쥐 하나만 쓴다. 표의 파일은 기록 저장소 `design/mascot/`의 원본 이름이고, 앱에서는 `MASCOT_IMAGES`의 식별자(`default` 등)로 불러온다.

| 식별자 | 파일 | 쓰는 곳 |
| --- | --- | --- |
| `mascot.default` | `squirrel-v2.png` | 소개, 시작 홈 |
| `mascot.discovery` | `squirrel-discovery-v1.png` | 빈 재료 목록 |
| `mascot.thinking` | `squirrel-thinking-v3.png` | 계산 중 |
| `mascot.meal` | `squirrel-meal-v1.png` | 결과 도입부 |
| `mascot.retry` | `squirrel-retry-straight-v4.png` | 추천 없음, 오류 |
| `mascot.question` | `question-mark-v1.png` | 소개 제목 영역(제목 영역 다람쥐의 머리 오른쪽 위). 고민, 탐색을 나타내는 보조 표현이다(다람쥐 그림이 아니다). 계산이 정상 진행 중인데 오류나 혼란으로 읽히지 않는지 확인하고 쓴다 |

- 종횡비를 유지하고 전체를 보여 준다. 꼬리, 손, 접시를 잘라 맞추지 않는다.
- 소개와 시작 홈 제목 영역의 다람쥐(`mascot.default`)는 화면 폭의 30%이고 104px에서 150px 사이다(`--mascot-header-size`). 물음표(`mascot.question`)는 다람쥐의 0.32배로 같이 줄어든다(`--mascot-question-size`). 다른 화면의 다람쥐는 각 화면에서 정한 크기를 쓴다.
- 다람쥐는 말하지 않는다. 대사나 말풍선 문구를 넣지 않는다.
- 진행 상황과 복구 행동은 글자와 버튼으로 제공한다. 안내 글이 같은 뜻을 전달하면 대체 텍스트는 비운다.
- 레시피 사진이나 재료 이미지를 대신하지 않는다.

## 재료 배분 표현

재료별 누적 막대와 요리별 펼침 내역으로 보여 준다.

| 토큰 | HEX | 쓰는 곳 |
| --- | --- | --- |
| `allocation.1` | `#6699CC` | 1번째 요리 |
| `allocation.2` | `#004488` | 2번째 요리 |
| `allocation.3` | `#EECC66` | 3번째 요리 |
| `allocation.4` | `#994455` | 4번째 요리 |
| `allocation.5` | `#44AA99` | 5번째 요리 |
| `allocation.remaining` | `#FAFAF7` | 남는 양 |

- 색은 재료가 아니라 요리에 붙인다. 요리 번호와 같은 번호의 색을 쓰고, 탭이나 묶음이 바뀌면 그 묶음의 번호로 다시 칠한다.
- 같은 묶음 안에서는 재료, 목록 순서, 펼침 상태가 달라도 요리의 색, 번호, 이름을 유지한다.
- 남는 양은 Light 빈 면, 먹색 경계, 남는 수량과 단위로 구분한다. 패턴은 넣지 않는다.
- 배분 표시는 Light 면 위에 놓는다. 글자와 숫자는 Ink를 쓴다.
- 색만으로 사용처를 전달하지 않는다. 범례와 내역에 요리 번호, 이름, 수량, 단위를 적는다.
- 공간이 충분한 막대 조각에는 번호를 넣을 수 있다. 작은 조각에 글자나 터치를 강요하지 않는다. 내역은 충분한 터치 영역으로 연다.
- 요리색에 정상, 실패, 긴급도 같은 의미를 주지 않는다.
- 막대마다 그 재료의 처음 양을 100%로 표시한다. 재료 사이의 막대 길이로 절대 수량을 비교하지 않는다.
- 처음 양은 각 요리 사용량 합과 남는 양을 더한 값이다. 막대 비율은 g 내부값으로 구한다. 작은 조각을 보이게 하려고 최소 폭을 부풀리지 않는다.
- 추가 구매분, 양념, 추천 점수는 가진 재료의 배분과 섞지 않는다.

## 잔량·수량 표기 규칙

요약, 배분 내역, 요리 카드, 장보기는 모두 `formatAmount`로 표시한다. 입력 단위 값은 g을 단위당 g으로 나눈 값이다. 요약과 배분 내역은 사용자가 입력한 단위를 유지한다.

| 값 | 표시 | 예 (양파 1개 = 200g) |
| --- | --- | --- |
| 실제 0 | `0` + 단위. 0은 이때만 쓴다 | 0개 |
| 0.1 단위 미만의 양수 | `0.1개 미만(g)`. g도 0.1g 미만이면 `0.1g 미만` | 10g → 0.1개 미만(10g) |
| ½ ⅓ ⅔ ¼ ¾에 정확히 맞는 값 | 분수. 1 이상은 정수와 붙여 쓴다 | 50g → ¼개, 250g → 1¼개 |
| 분수는 아니지만 소수 한 자리로 정확히 맞는 값 | 소수 | 40g → 0.2개 |
| 그 밖의 값 | `약` + 소수 한 자리. 끝의 .0은 쓰지 않는다 | 74g → 약 0.4개 |
| g 입력 | g, 소수 한 자리까지 | 37.5g |

- 정확한 값은 g으로 되돌렸을 때 차이가 0.1g 이하인 값이다. 앱 데이터의 g이 0.1g 단위로 반올림돼 오기 때문이다. 분수 후보는 가장 가까운 값을 쓴다.
- ⅛ 계열은 쓰지 않는다.
- 다 썼는지 판정은 표시와 별개다. 남은 양 1g 미만은 "다 써요"로 분류하지만, 수량을 보여 주는 자리에는 실제 양을 표시한다.
- 근삿값이 섞이면 표시한 부분의 합이 표시한 전체와 다를 수 있다. `amountsReconcile`이 `false`면 그 사실을 부가 설명으로 적을 수 있다. 합을 맞추려고 표시 값을 조정하지 않는다.

- 매 입력마다 긴 등장 연출을 재생하지 않는다.

## 접근성과 확인

- 일반 글자 대비는 4.5:1 이상, 식별에 필요한 그래픽과 상태 표식은 3:1 이상이어야 한다. 장식 구분선에는 이 기준을 적용하지 않는다.
- 선택 상태는 색 외에 체크, 테두리, 문구로 표시한다.
- 포커스는 블루 외곽선과 간격으로 표시한다.
- 키보드 포커스, 입력 label과 오류 연결, 화면 읽기 순서, 사용자 확대를 확인한다.
- 360px, 390px 폭에서 긴 제목, 요리명, 수량, 단위가 넘치거나 잘리지 않는지 확인한다.
- 가상 키보드가 값, 오류, 다음 행동을 가리지 않는지 실제 기기에서 확인한다.
- 색각 시뮬레이션만으로 접근성 확인을 끝내지 않는다.
