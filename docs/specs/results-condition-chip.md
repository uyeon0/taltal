# 결과 화면 조건 칩

추천 결과 화면의 "재료 수정"을 머리글 뒤로가기 버튼에서 빼고, 머리글 아래의 조건 칩으로 옮긴다. 조건 칩은 결과를 낸 재료와 인분을 보여 주고, 누르면 재료 입력으로 간다. 웹과 앱인토스 미니앱이 같은 칩을 쓴다.

미니앱에서 머리글을 빼는 일은 이 작업에 넣지 않는다. 이 작업이 끝난 뒤 따로 한다.

## 배경

- 앱인토스 출시 체크리스트는 토스 내비게이션 바의 뒤로가기와 미니앱 자체 뒤로가기를 함께 보여 주지 못하게 한다. 지금 결과 화면의 "재료 수정"은 머리글 뒤로가기 버튼이라, 미니앱에서 머리글을 빼면 같이 사라진다.
- "재료 수정"을 뒤로가기가 아닌 화면 안의 버튼으로 옮기면, 미니앱에서 머리글을 빼도 재료를 고치는 길이 남는다. 웹과 미니앱이 같은 버튼을 쓰므로 분기가 생기지 않는다.
- 숙소 검색 앱(Marriott Bonvoy, Booking.com, Skyscanner)은 결과 위에 검색 조건 요약을 두고, 그것을 눌러 조건을 고치게 한다. 시각 레퍼런스 Yellowbird의 상품 목록은 큰 제목 아래에 먹색 윤곽의 밝은 칩을 둔다. 조건 칩은 두 방식을 합친 것이다.
- 재료 칩과 인분 칩을 나눈 안도 프로토타입으로 비교했다. 둘 다 재료 입력으로 가므로 칩 하나로 정했다.

## 결정

| 항목 | 결정 |
| --- | --- |
| 칩 개수 | 하나. 재료와 인분을 한 칩에 쓴다 |
| 칩 문구 | `{재료1} · {재료2} 외 {N}개 · {인분}인분`. 재료가 2개 이하면 "외 {N}개"를 빼고 모두 쓴다 |
| 재료 순서 | 재료 입력 목록의 순서 |
| 누르면 | 재료 입력으로 간다. 앱 안 기록이 있으면 `router.back()`, 없으면 `/ingredients`. 지금 "재료 수정" 버튼과 같다 |
| 아이콘 | 칩 오른쪽 끝에 연필(`lucide-react`의 `Pencil`) |
| 모양 | Secondary 버튼과 같다. Light 면, Ink 글자, Ink 선, 모서리 `--radius`, hover와 pressed는 블루 |
| 너비 | 화면 폭에서 좌우 여백을 뺀 전체. 넘치는 글자는 말줄임표로 자른다 |
| 위치 | 머리글 바로 아래. 스크롤해도 화면 위에 붙는다 |
| 아래 선 | 칩 줄 아래를 앱 폭 전체의 3px Ink 선으로 나눈다. 지금 머리글 아래 선을 옮긴 것이다 |
| 머리글 | 서비스 이름만 둔다. 뒤로가기 버튼을 두지 않고, 위에 붙지 않는다 |
| 인분 줄 | 제목 아래의 "각 요리 {인분}인분 기준"을 지운다. 칩이 같은 정보를 보여 준다 |
| 화면 읽기 이름 | `재료 수정: {칩 문구}` |
| 상태 | 계산 중, 결과, 추천 없음, 오류 모두 같은 칩을 보여 준다 |

추천 없음과 오류 화면의 "재료 수정하기" 버튼은 그대로 둔다. 그 화면의 주 행동이기 때문이다.

## 테스트

- `results-screen.test.tsx`
  - 조건 칩에 재료와 인분이 보인다.
  - 재료가 3개 이상이면 "외 {N}개"로 줄인다.
  - 칩을 누르면 재료 입력으로 간다. 앱 안 기록이 있을 때와 없을 때를 나눈다.
  - 지금 머리글의 "재료 수정" 버튼을 찾는 테스트는 조건 칩을 찾도록 고친다.
- 칩 문구를 만드는 함수는 따로 단위 테스트를 둔다.

## 확인

- lint, 타입 검사, 테스트, `fsd-review`
- 휴대폰 폭 브라우저에서 결과 화면을 열고 확인한다.
  - 칩에 재료와 인분이 보인다.
  - 긴 목록을 내려도 칩 줄이 위에 붙어 있다.
  - 요리 카드를 열었다 닫아도 카드가 칩 줄에 가려지지 않는다.
  - 칩을 누르면 재료 입력으로 가고, 입력이 그대로 남아 있다.
- 재료 이름이 긴 경우(예: "노랑 파프리카")에도 칩이 한 줄을 넘지 않는다.

## 정리

프로토타입 브랜치 `proto/results-condition-chips`는 이 작업의 브랜치를 만들기 전에 지운다. 프로토타입 코드는 가져오지 않는다.
