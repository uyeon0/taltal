# 화면 레이아웃 보정

좁은 폭(320px), 낮은 화면, 높은 화면에서도 소개와 시작 홈이 자연스럽게 보이게 하고, 재료 입력의 아래 고정 영역이 휴대폰 주소창이 움직일 때 깜빡이지 않게 한다. 한 번에 하나씩 고치고, 각 변경은 실제 앱에 넣은 시안으로 확인한 뒤 정한다.

- 기준 문서: `docs/requirements/onboarding.md`, `docs/requirements/ingredient-input.md`, `docs/design.md`

| 2 | 소개 미리 보기와 화면 높이 (소개) | 이 문서에서 정함 |

## 1. 제목 영역 구조

### 문제

320px에서 제목과 안내 문구가 다람쥐 옆 좁은 칸을 나눠 쓴다. 소개는 제목("이 재료들을 / 어떻게 다 / 먹지?")과 설명이 3줄로, 시작 홈은 안내 문구가 "가진 재료부터 담아 / 주세요."로 어색하게 줄바꿈된다.

### 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 구조 | 제목과 다람쥐를 한 줄에 두고, 설명(소개)과 시작 안내(시작 홈)는 그 아래에 화면 폭 전체로 둔다 | 설명이 다람쥐 옆 칸에서 줄바꿈되지 않는다 |
| 다람쥐 오른쪽 여백 | 두지 않는다 | 따로 겹쳐 그리던 물음표의 자리였다. 물음표가 그림에 들어 있다 |
| 다람쥐 왼쪽 겹침 | `-ml-4`(16px)로 제목 칸 쪽에 겹친다 | 그림의 왼쪽 약 12%가 비어 있어 꼬리가 제목에 닿지 않는다 |
| 다람쥐 크기 | `--mascot-header-size: clamp(6rem, 30vw, 9.375rem)`. 96px에서 150px 사이 | 320px에서 제목 칸이 200px이 돼 "어떻게 다 먹지?"(28px에서 191px)에 여유가 생긴다. 347px보다 넓으면 지금과 같다 |
| 제목 글자 | 모든 폭에서 28px(`text-display-sm`) | 다람쥐 크기로 여유를 만들었으므로 글자를 줄이지 않는다 |
| 간격 | 바깥 틀 `gap-3 pt-4 pb-4`, 제목 줄 `gap-2` | 설명이 아래로 내려오면서 위아래 균형을 맞춘다 |

### 시안에서 잰 값

| 폭 | 다람쥐 | 제목 칸 | 소개 제목 | 소개 설명 | 시작 홈 안내 |
| --- | --- | --- | --- | --- | --- |
| 320px | 96px | 200px | 2줄 | 2줄 | 1줄 |
| 340px | 102px | 214px | 2줄 | 2줄 | |
| 375px | 113px | 239px | 2줄 | 2줄 | 1줄 |
| 448px | 134px | 290px | 2줄 | 1줄 | |

## 2. 소개 미리 보기와 화면 높이

### 문제

- 높은 화면에서 소개 캐러셀(3:2)과 시작 버튼 사이가 크게 빈다.
- 미리 보기 모형이 작은 글자 여러 줄이라 레퍼런스(Yellowbird)의 "적게, 크게"와 어긋난다. 2장의 검정 알약 태그(`1번째 요리`)가 특히 어색하다.
- 휴대폰에서 스크롤해 주소창이 접히면 시작 버튼 아래에 Light 면이 드러난다.

### 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 정보 | 모든 화면 높이에서 같은 내용을 보여 준다. 화면 크기로 내용을 숨기지 않는다 | 화면에 따라 설명을 덜 보는 사람이 생기지 않게 한다. 글자를 키운 사람에게는 숨겨도 넘친다 |
| 크기 | 낮은 화면은 촘촘하게, 높이 860px 이상(`tall` 변형)은 같은 내용을 크게 그린다 | 360×640에서 한 화면에 들어가고, 높은 화면은 빈 곳을 크기로 채운다 |
| 넘칠 때 | 숨기거나 자르지 않고 페이지가 스크롤된다 | 320×568에서는 72px 넘친다 |
| 1장 | 카드 머리 줄("담은 재료 4개", "2인분") 아래에 재료 4줄(두부 300g, 대파 1단, 계란 5개, 양파 1개) | 인분을 칩이나 상자로 그리면 누를 수 있어 보인다. 머리 줄은 설명 글로 읽힌다 |
| 2장 | 요리마다 두 줄. 첫 줄은 색 점과 요리명, 둘째 줄은 쓰는 재료("두부 100g · 대파 ¼단 · 양파 ½개") | 순서 태그와 남는 재료 줄은 두지 않는다. 남는 양은 3장이 보여 준다 |
| 3장 | 두부 막대 바로 아래에 요리 색 설명(요리명만), 그 아래 대파, 계란, 양파 막대 | 세 요리가 모두 나오는 두부 막대에 색 설명을 붙인다. 양을 빼서 한 줄에 들어간다 |
| 예시 값 | 1장 재료 4개가 3장에서 모두 막대로 나오고, 2장의 요리별 재료 양이 3장 막대와 맞는다 | 세 장이 예시 하나를 이어 쓴다 |
| 캐러셀 높이 | 비율을 두지 않고 가장 긴 장의 높이를 따른다. 짧은 장의 모형은 세로 가운데에 둔다 | 폭으로 높이를 정하면 낮은 화면에서 모형이 들어가지 않는다 |
| 장 제목 | 줄을 바꾸지 않는다. 글자 크기는 `clamp(1rem, 5.3vw, 1.5rem)`이다 | 가장 긴 제목이 360px에서 한 줄(약 19px)에 들어간다 |
| 제목 영역(소개) | 낮은 화면에서 다람쥐 80px, 설명 `text-base`, 간격 `gap-2 py-3`. `tall`에서는 1절의 값 | 360×640에서 207px을 139px로 줄여 캐러셀 자리를 만든다 |
| 페이지 높이 | `min-h-svh` | `dvh`는 주소창이 움직일 때마다 높이를 다시 계산해 깜빡인다 |
| 시작 버튼 영역 | `fixed`로 화면 바닥에 붙이고, 그 높이만큼 페이지 아래를 비운다 | `sticky`는 페이지 끝을 따라가서 주소창이 접히면 바닥에서 뜬다 |
| 바깥 배경 | 화면 폭이 앱 열(448px) 이하이면 `body`도 주황이다 | 주소창이 접혀 앱 열 아래가 드러나도 Light 면이 보이지 않는다 |

시작 홈의 제목 영역은 이번에 바꾸지 않는다. 시작 홈은 캐러셀이 없어 낮은 화면에서도 넘치지 않는다.

### 시안에서 잰 값

| 화면 | 제목 영역 | 장 제목 | 결과 |
| --- | --- | --- | --- |
| 320×568 | 163px | 약 17px | 72px 넘쳐 페이지가 스크롤된다 |
| 360×640 | 139px | 약 19px | 세 장 모두 한 화면에 들어간다 |
| 448×960 | 207px | 약 24px | 세 장 모두 한 화면에 들어간다 |

컴퓨터 브라우저의 좁은 창은 마우스 환경이라 슬라이드 좌우 간격이 48px이다. 그래서 320px 창에서는 2장 두부찌개 재료가 두 줄이 되지만, 터치 휴대폰에서는 한 줄이다.

## 3. 재료 입력 페이지 높이

### 문제

재료 입력의 페이지 높이가 `min-h-dvh`라서 휴대폰에서 주소창이 움직일 때마다 높이를 다시 계산해 깜빡인다.

### 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 페이지 높이 | `min-h-svh` | 2절의 소개와 같다 |
| "요리 찾기" 줄 | `fixed`와 줄 높이를 재서 비우는 아래 여백을 그대로 둔다 | 줄 높이가 비활성 이유 문구와 직접 입력 중 숨김에 따라 바뀐다 |

### 구현

| 파일 | 바꿀 내용 |
| --- | --- |
| `src/_pages/ingredients/ui/ingredient-input-screen.tsx` | `min-h-dvh`를 `min-h-svh`로 바꾼다 |

### 확인

- lint, 타입 검사, 테스트
- 휴대폰에서 재료를 담고 스크롤해 주소창이 접혀도 "요리 찾기" 줄이 바닥에 붙어 있고 깜빡이지 않는다
