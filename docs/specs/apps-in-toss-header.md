# 미니앱 헤더 제거

앱인토스 미니앱에서는 `AppHeader`를 그리지 않고 16px 여백만 남긴다. 토스 내비게이션 바가 앱 이름과 뒤로가기를 맡는다. 웹은 바꾸지 않는다. 요구사항은 `docs/requirements/apps-in-toss.md`의 "헤더"이다.

## 배경

- 토스 내비게이션 바가 앱 이름을 보여 주므로, 헤더의 서비스 이름도 같은 내용이 두 번 보인다.

## 구현

| 파일 | 바꿀 내용 |
| --- | --- |
| `src/shared/ui/app-header.tsx` | `IS_AIT`이면 헤더 대신 높이 `--page-gutter`(16px)의 빈 칸을 돌려준다 |
| `src/shared/ui/app-header.test.tsx` | 새로 만든다. 웹에서는 헤더와 뒤로가기가 있고, 미니앱에서는 헤더와 버튼 없이 빈 칸만 있는지 확인한다 |

화면 코드는 바꾸지 않는다. 환경 분기는 `AppHeader` 한 곳이다.

빈 칸을 두는 이유: 헤더(65px)을 통째로 빼면 내용이 토스 내비게이션 바 아래 8px에서 시작해 답답해 보였다(QR 테스트). 16px을 더해 위 여백을 24px로 맞춘다. 화면 안 구역 사이 간격(`gap-6`)과 같은 값이다.

## 미니앱에서 달라지는 동작

| 화면 | 웹 | 미니앱 |
| --- | --- | --- |
| 재료 입력의 뒤로 | 앱 안 기록이 있으면 뒤로, 없으면 `/` | 토스 뒤로가기. 이전 화면이 있으면 뒤로, 없으면 미니앱을 닫는다 |
| 결과의 조건 칩 줄 | 헤더 아래에서 시작해 스크롤하면 맨 위에 붙는다 | 16px 여백 아래에서 시작해 스크롤하면 맨 위에 붙는다 |
| 시트를 닫은 뒤 포커스 | 연 버튼을 찾지 못하면 헤더 뒤로가기 버튼으로 간다 | 연 버튼을 찾지 못하면 돌려줄 곳이 없다 |

- 미니앱은 `intoss://taltal`로 열려 시작 홈에서 시작하고, 재료 입력에는 시작 홈에서 들어온다. 그래서 재료 입력에서 토스 뒤로가기를 누르면 시작 홈으로 돌아갈 것으로 본다. 경로가 붙은 딥링크로 재료 입력을 바로 열면 뒤로가기가 미니앱을 닫는다. 지금은 그런 링크를 쓰지 않는다.
- 토스 웹뷰가 새로고침할 때 기록을 어떻게 다루는지는 확인하지 못했다.

## 확인

- lint, 타입 검사, 테스트, `fsd-review`
- 웹 빌드에서 네 화면의 헤더가 그대로인지 본다.
- 미니앱 번들을 올려 QR로 확인한다.
  - 소개, 시작 홈, 재료 입력, 결과에 앱 헤더가 없다.
  - 시작 홈 → 재료 입력에서 토스 뒤로가기를 누르면 시작 홈으로 돌아온다.
  - 재료 고르기 시트와 레시피 상세 시트가 토스 뒤로가기로 닫힌다.
  - 결과 화면의 조건 칩이 맨 위에 붙어 있다.
