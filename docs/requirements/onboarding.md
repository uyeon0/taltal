# 소개와 시작 홈

첫 방문 소개와 시작 홈의 요구사항을 정한다. 비슷한 앱을 써 본 사람이 거의 없어서 레시피 하나를 추천하는 앱으로 오해하기 쉽다. 소개는 재료를 여러 요리에 나눠 쓴다는 점을 먼저 알린다.

배치는 `docs/wireframes/home-first-visit.html`, `docs/wireframes/home-returning.html`을 참고하고, 화면 인상은 `docs/wireframes/ingredient-input-style-study.html`의 첫 화면을 참고한다. 문구는 `docs/copy.md`를 따른다.

## 소개

첫 방문에만 나오는 화면이다. 헤더를 포함한 화면 전체가 주황 면이다.

| 순서 | 구성 |
| --- | --- |
| 1 | 헤더 로고 |
| 2 | 제목과 설명. 장을 넘겨도 움직이지 않는다 |
| 3 | 캐러셀. 3단계를 장 3개로 보여 준다. 높이는 가장 긴 장을 따른다 |
| 4 | 점 표시 |
| 5 | 시작 버튼. 화면 바닥에 고정된다 |

- 장은 옆으로 넘긴다. 휴대폰에서는 스와이프로, 마우스 환경에서는 캐러셀 좌우 끝의 화살표 버튼과 드래그로 넘긴다. 점 표시를 눌러서도 옮긴다.
- 장마다 그 단계의 문구와 그 단계의 화면을 줄인 미리 보기가 있다. 장 문구는 줄을 바꾸지 않고, 좁은 화면에서는 글자가 작아진다.
- 미리 보기는 실제 화면의 핵심 요소만 앱 화면과 같은 모양으로 다시 그린 모형이다. 1장은 재료 입력의 담은 재료 목록과 인분, 2장은 추천 결과의 요리 묶음과 요리마다 쓰는 재료, 3장은 사용량 시트의 재료 막대와 남는 양이다.
- 세 장은 두부를 요리 3가지에 나눠 쓰고 얼마가 남는지 보여 주는 가상 예시 하나를 이어 쓴다. 1장의 재료는 3장에서 모두 막대로 나오고, 2장의 요리별 재료 양은 3장 막대와 맞는다. 예시 값은 고정 값이고 실제 추천을 실행하지 않는다.
- 미리 보기는 모든 화면 높이에서 같은 내용을 보여 준다. 낮은 화면에서는 촘촘하게, 높은 화면에서는 크게 그린다. 넘치면 내용을 숨기지 않고 페이지가 스크롤된다.
- 미리 보기는 모형 자체를 장 제목 아래 남는 공간의 세로 가운데에 둔다. 좌우 화살표도 모형의 세로 가운데에 맞춘다.
- 미리 보기는 장의 문구를 보충하는 그림이라 화면 읽기 프로그램에는 읽히지 않는다.
- 제목 영역의 다람쥐는 화면 폭에 맞춰 줄어든다. 폭의 30%이고 96px에서 150px 사이다. 소개는 낮은 화면(높이 860px 미만)에서 다람쥐를 80px로 줄여 캐러셀 자리를 만든다. 설명은 제목과 다람쥐 아래에 화면 폭 전체로 둔다. 물음표는 다람쥐 그림에 함께 그려져 있어 같이 줄어든다. 시작 홈의 다람쥐도 같은 규칙을 쓴다.
- 시작 버튼은 모든 장에서 보인다. 누르면 방문 여부를 저장하고 시작 홈으로 간다. 이후 방문에서는 소개를 보여 주지 않는다.
- 작은 화면에서도 시작 버튼이 항상 닿는 곳에 있어야 한다.

## 시작 홈

재방문과 소개 뒤에 도착하는 화면이다.

| 순서 | 구성 |
| --- | --- |
| 1 | 헤더 로고 |
| 2 | 넓은 주황 상단 면: 큰 제목, 시작 안내, 다람쥐(`mascot.default`) |
| 3 | Light 영역: "직접 고르기" 주 행동 |
| 4 | 예시 요리 묶음 캐러셀 |

- "직접 고르기"를 누르면 재료 입력으로 가면서 재료 선택 시트를 연다.
- 재료 입력에서 뒤로 가면 시작 홈으로 돌아오고, 담은 재료는 유지된다.
- 시작 홈은 입력을 받지 않는다. 기본 양념 목록은 재료 입력에만 둔다.
- 첫 화면에서 스크롤 없이 "직접 고르기"가 보여야 한다.

### 예시 요리 묶음

시작 홈이 비어 보이지 않게, 장 본 재료가 요리 몇 가지에 어떻게 나뉘는지 예시로 보여 준다.

- "직접 고르기" 아래에 둔다. 예시를 넣어도 "직접 고르기"의 위치는 바뀌지 않는다.
- 묶음 3개를 장 하나에 하나씩 보여 주고 옆으로 넘긴다. 보이는 장은 화면 가운데에 두고, 양옆에 이웃 장의 끝이 보여서 넘길 수 있다는 것을 알린다. 점 표시와 화살표 버튼은 두지 않는다.
- 예시 묶음은 가진 재료를 모두 다 쓰는 묶음만 고른다. 재료가 남는 예시는 서비스가 재료를 다 쓰게 해 주지 못한다는 인상을 준다.
- 장마다 가진 재료와 양, 가진 재료를 다 쓴다는 문장, 요리 3가지, 따로 사는 재료를 보여 준다. 다 쓴다는 문장을 요리 목록보다 위에 둔다.
- 요리마다 순서 번호와 이름을 한 줄에, 이 요리에 쓰는 가진 재료와 양을 다음 줄에 쓴다. 양은 결과 화면과 같은 표기(`formatAmount`)를 쓴다.
- 따로 사는 재료는 묶음 전체에서 모아 카드 끝에 이름만 한 줄로 쓴다. 있으면 좋은 재료는 쓰지 않는다.
- 예시 값은 고정 값이고 실제 추천을 실행하지 않는다. 실제 레시피 데이터로 추천 함수를 돌린 결과를 옮겨 둔다. 화면에 "예시" 표시는 두지 않고, 화면 읽기 프로그램에는 캐러셀 이름으로 예시라는 것을 알린다.
- 예시는 입력을 받지 않는다. 장이나 요리를 눌러도 재료를 담거나 화면을 옮기지 않는다.
- 점 표시가 없으므로 모든 장을 화면 읽기 프로그램이 읽을 수 있게 둔다. 키보드로 장에 포커스가 가면 그 장이 보이도록 넘긴다.

## 확인 기준

- 첫 방문에는 소개가, 소개를 지난 뒤와 재방문에는 시작 홈이 나온다. 소개가 잠깐 보였다가 사라지지 않는다.
- 360px, 390px 폭에서 제목과 다람쥐가 겹치지 않고 가로로 넘치지 않는다.
- 낮은 화면에서도 "직접 고르기"가 첫 화면에 보인다.
- 소개와 시작 홈의 다람쥐가 잘리지 않는다. 대체 텍스트는 모두 비어 있다.
- 시작 버튼과 점 표시가 360×640 화면에서 함께 보인다. 시작 버튼은 모든 장에서 같은 자리에 있고, 휴대폰에서 주소창이 접혀도 화면 바닥에 붙어 있다.
- 소개의 장을 휴대폰에서는 스와이프로, 마우스 환경에서는 화살표 버튼으로 넘길 수 있고, 키보드로는 점 표시로 옮길 수 있다. 화살표 버튼은 휴대폰에서 보이지 않는다.
- 360×640에서 소개가 스크롤 없이 한 화면에 들어간다.
- 360px, 390px에서 소개의 제목이 두 줄이다. 높은 화면에서 다람쥐는 360px에서 108px, 390px에서 117px이고 500px 이상에서도 150px를 넘지 않는다.
- 360px 이상에서 소개의 장 문구가 한 줄이다.
- 동작 줄이기에서 장이 움직임 없이 바뀐다.
- 360px, 390px 폭에서 세 장의 미리 보기 모형이 장 밖으로 넘치거나 잘리지 않는다. 320×568처럼 넘치는 화면에서는 페이지가 스크롤돼 모두 볼 수 있다.
- 시작 홈의 예시 묶음을 넣어도 360×560에서 "직접 고르기"가 스크롤 없이 보인다.
- 시작 홈의 예시 묶음을 휴대폰에서는 스와이프로, 마우스 환경에서는 드래그로 넘길 수 있고, 키보드로 장에 포커스를 옮기면 그 장이 보인다. 화면 읽기 프로그램은 세 장을 모두 읽는다.
- 360px, 390px 폭에서 예시 묶음의 재료, 요리명, 양이 잘리거나 가로로 넘치지 않는다.
