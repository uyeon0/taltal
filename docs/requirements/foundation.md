# 앱 공통 요구사항

모든 화면이 함께 지켜야 하는 동작을 정한다. 시각 값은 `docs/design.md`를, 화면 흐름은 `docs/overview.md`를, 문구는 `docs/copy.md`를 따른다.

## 앱 영역

- 앱은 가운데 448px 열 하나로 보인다. 그보다 넓은 화면에서 바깥은 Light이고, 앱 영역 좌우에 2px Ink 선이 있다.
- 브라우저 탭의 제목과 설명, 공유 미리보기는 서비스 이름과 한 줄 설명을 쓴다.
- 머리글 로고와 파비콘은 한 곳에서 불러온다. 파일을 바꾸면 모든 화면에 반영된다.

## 화면 전환과 상태

- 재료, 수량, 단위, 인분은 화면을 오가도 유지되고, 새로고침하면 초기화된다.
- 소개는 첫 방문에만 나온다. 다시 방문하면 시작 홈에서 시작하고, 소개가 잠깐 보였다가 사라지면 안 된다.
- 소개를 뺀 화면과 바텀시트는 브라우저 기록에 들어간다. 휴대폰의 뒤로가기는 앱을 나가지 않고 열린 시트를 닫거나 이전 화면으로 돌아간다.

## 바텀시트

재료 선택, 사용량, 레시피 상세는 같은 바텀시트로 연다.

- 시트 안의 스크롤과 본문 스크롤은 섞이지 않는다.
- 시트를 닫으면 포커스가 시트를 연 버튼으로 돌아가고, 본문 스크롤 위치를 유지한다.
- 그 버튼이 다시 그려졌으면 같은 뜻의 버튼으로 돌아가고, 없으면 뒤로가기 버튼으로 돌아간다.
- 가상 키보드가 열리면 시트의 입력칸과 주 행동이 가려지지 않는다.

## 로딩과 오류

- 화면을 기다리는 동안 스피너와 바뀌는 문구를 보여 준다. 규칙은 `docs/design.md`의 "컴포넌트 상태"를 따른다.
- 오류와 안내는 같은 상태 메시지 형식으로 보여 준다.
- 오류가 나도 입력한 재료는 유지된다.

## 이미지

- 재료 이미지는 재료 ID로 찾는다. 변형 재료는 그림 하나를 함께 쓸 수 있다.
- 이미지가 없는 재료도 화면이 깨지지 않고 이름, 수량, 선택 동작을 유지한다.
- 다람쥐 이미지는 `docs/design.md`의 식별자로 불러온다.

## 문구

화면의 문구는 코드의 한 파일에서 가져온다. 화면 코드에 직접 쓰지 않는다.

## 사용 기록

유저 테스트에서 사용자가 어디서 막혔는지 보려고 Microsoft Clarity 세션 녹화를 쓴다.

- 프로젝트 ID는 환경 변수로 넣는다. 값이 없으면 스크립트를 불러오지 않는다.
- 재료 이름과 양은 녹화에서 가리지 않는다. 개인정보가 아니고 테스트 장바구니로 쓰기 때문이다.
- 사용 기록이 남는다는 사실은 테스트 모집 글과 피드백 폼에서 알린다.

## 확인 기준

- 360px, 390px, 448px보다 넓은 폭에서 앱 영역이 깨지지 않는다.
- 동작 줄이기에서 전환이 0ms다.
- 키보드만으로 시트를 열고 닫을 수 있고, 포커스 표시가 보인다.
- 낭만있구미체로 쓴 제목에 빈 글자가 없다.
- 코드에 `docs/design.md`의 값과 다른 임의 색, 간격, 라운딩, 그림자, 투명도가 없다.
