# 레시피 상세

요리 카드를 누르면 여는 레시피 상세 시트의 요구사항을 정한다. 사용자가 요리하기 직전에 이 요리에 무엇을 얼마나 쓰는지와 만드는 법을 확인하는 곳이다.

구성은 `docs/wireframes/recipe-results-wireframe.html`의 상세 시트를 참고한다. 데이터는 `docs/data-contract.md`를, 문구는 `docs/copy.md`를 따른다.

## 불러오기

- 시트를 열면 `GET /api/recipes/[id]`로 그 레시피의 `RecipeDetail` 하나만 받는다. 레시피 전체를 미리 받지 않는다.
- 받는 동안 시트 안에 로딩 표시를 둔다. 시트 제목과 재료 목록은 결과 데이터로 먼저 보여 줄 수 있다.
- 받지 못하면 시트 안에 오류 안내를 보여 준다. 결과 화면과 입력한 재료는 그대로다.

## 구성

위에서 아래로 다음 순서로 둔다.

| 순서 | 구성 |
| --- | --- |
| 1 | "N번째 요리", 요리 이름, 조리 시간 |
| 2 | 요약(`RecipeDetail.summary`) |
| 3 | 이 요리에 쓰는 재료 |
| 4 | 만드는 법 |

## 이 요리에 쓰는 재료

`Recipe.ingredients`에 있는 재료를 모두 보여 준다. 세 무리로 나눈다.

| 무리 | 양 |
| --- | --- |
| 가진 재료 | `Meal.uses`의 양을 사용자가 입력한 단위로 쓴다. 원문 분량(`amountText`)은 접어 두고 펼쳐 볼 수 있다 |
| 사야 하는 재료 | 결과 화면의 요리 카드와 같은 양을 쓴다. 다른 재료와 구분해 눈에 띄게 쓴다 |
| 양념 | 원문 분량(`amountText`)을 그대로 쓴다 |

- 양념은 g이 없어 인분에 맞춰 바꾸지 못한다. 그래서 원문이 몇 인분 기준인지(`servingsOriginal`) 함께 쓴다.
- 물과 육수는 데이터에 없으므로 재료 목록에 나오지 않는다. 조리 과정의 글로 확인한다.

## 만드는 법

- `steps`를 `no` 순서로 보여 준다. `tip`이 있으면 그 단계 아래에 붙인다.
- 원본 데이터에 사진이 없으므로 글로만 보여 준다.

## 시트 동작

- 긴 레시피도 시트 안에서 끝까지 스크롤할 수 있다. 시트 안 스크롤과 결과 화면 스크롤은 섞이지 않는다.
- 시트를 닫으면 누른 요리 카드로 포커스와 스크롤 위치가 돌아간다. 규칙은 `docs/requirements/foundation.md`의 "바텀시트"를 따른다.
- 브라우저 뒤로가기로 시트를 닫을 수 있다.

## 확인 기준

- 시트를 열 때 그 레시피 하나만 요청한다.
- 가진 재료의 양이 결과 화면의 요리 카드와 같은 단위와 값으로 보인다.
- 양념에 원문 인분 안내가 붙어 있다.
- 응답이 실패해도 시트 안에서 안내하고, 닫으면 결과 화면이 그대로다.
- 마지막 요리 카드를 열고 닫은 뒤 같은 카드로 돌아온다.
