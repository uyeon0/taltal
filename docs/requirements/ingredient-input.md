# 재료 입력

사용자가 가진 재료와 양, 인분을 넣는 화면과 재료 선택 시트의 요구사항을 정한다. 입력한 양이 추천의 기준이므로 양을 빠르게 넣으면서도 추정 없이 받는다.

세부 동작은 `docs/wireframes/ingredient-input-wireframe.html`을, 화면 사이의 상태 전달은 `docs/wireframes/integrated-flow-wireframe.html`을 참고한다. 화면 인상은 `docs/wireframes/ingredient-input-style-study.html`을 참고한다. 문구는 `docs/copy.md`를 따른다.

## 화면 구성

위에서 아래로 다음 순서로 둔다.

| 순서 | 구성 |
| --- | --- |
| 1 | 제목 |
| 2 | 담은 재료 목록. 비어 있으면 빈 목록 안내와 다람쥐(`mascot.discovery`) |
| 3 | 재료 추가 버튼 |
| 4 | 기본 양념 안내와 접힌 목록 |
| 5 | 인분 선택 |
| 6 | 화면 아래 고정 주 행동 |

## 재료 선택 시트

- 시트에는 검색칸, 재료 격자, 담기 버튼이 있다.
- 재료는 `pantry`가 `null`인 재료만 보여 준다. 레시피에 많이 나오는 재료를 앞에 둔다.
- 검색은 `Ingredient.id`와 `aliases`에서 찾는다.
- 재료 칸에는 재료 이미지와 이름을 함께 표시한다.
- 여러 재료를 고른 뒤 한 번에 담는다. 재료 하나를 고를 때마다 시트를 닫지 않는다.
- 고르기만 하거나 시트를 닫으면 담은 재료 목록은 바뀌지 않는다.
- 검색으로 가려진 재료도 선택 상태를 유지한다.
- 이미 담은 재료는 고를 수 없고 "담김"으로 표시한다.
- 검색 결과가 없고 양념도 맞지 않으면 안내 문구와 검색어 지우기를 보여 준다. 목록에 없는 재료를 직접 적어 넣는 기능은 없다.
- 양념은 목록에 보이지 않지만 검색에는 응답한다. 재료가 하나도 맞지 않고 양념이 맞으면 재료 격자 자리에 양념 안내를 보여 준다. 재료가 하나라도 맞으면 양념 안내는 보여 주지 않는다.
- 담으면 시트를 닫고 첫 번째 재료의 수량 편집을 펼친다.

### 양념 검색 안내

- 검색어는 양념의 `id`와 `aliases`에서 찾는다. `aliases`의 "[불고기양념] 간장"처럼 대괄호로 묶은 앞부분은 요리 이름이라 빼고 찾는다.
- 안내는 종류별로 다르다. `pantry`가 `"기본"`이면 있다고 보고 계산한다고, `"특수"`면 넣지 않아도 되고 요리에 필요하면 요리 카드에 "필요한 양념"으로 알려 준다고 쓴다.
- 안내에 쓰는 이름은 검색어가 아니라 양념의 `id`다. "다진마늘"을 찾으면 "마늘"로 쓴다. 맞는 양념이 여럿이면 종류마다 이름을 쉼표로 이어 한 문장으로 쓴다.
- 안내는 격자 자리에 두고 검색어 지우기는 두지 않는다. 화면 읽기 프로그램이 검색할 때마다 읽도록 상태 영역(`role="status"`)으로 둔다.

## 수량 입력

가진 양 입력은 필수다. 기본값을 넣지 않는다. 사용자가 양을 정하지 않은 재료로 추천하면 결과를 믿을 수 없기 때문이다.

- 담은 재료는 이미지, 이름, 정한 양을 한 줄로 보여 준다. 양을 정하지 않은 재료는 그 사실을 글자로 표시한다.
- 수량 편집은 한 번에 재료 하나만 펼친다. 목록의 재료를 다시 누르면 편집이 열린다.
- 수량을 정하면 다음 미완료 재료가 펼쳐진다. 미완료 재료가 없으면 편집을 닫는다.
- "재료 삭제"로 재료를 뺀다.

### 빠른 수량 버튼

재료의 `inputUnits[0]` 단위로 버튼 세 개를 보여 준다. 재료 데이터에 버튼 값이 없으므로 다음 규칙으로 계산한다.

| 단위 | 버튼 값 | 예 |
| --- | --- | --- |
| g | 100, 200, 300 | 쇠고기 100g |
| 단위 하나가 100g 미만 | 2, 5, 10 | 계란 5개, 깻잎 10장 |
| 그 밖의 단위 | ½, 1, 2 | 양파 ½개, 대파 1단 |

### 직접 입력

- 직접 입력은 접어 두고 사용자가 누를 때만 펼친다.
- 숫자 키패드(`inputmode="decimal"`)를 연다.
- 허용 범위는 0 초과, 100,000 이하다. g으로 바꾼 값이 10,000,000g을 넘어도 같은 오류를 보여 준다. 서버 API가 재료 하나에 그만큼까지만 받기 때문이다. 벗어나면 그 자리에 오류를 보여 주고 입력칸과 연결한다.
- 단위는 `inputUnits`에서 고른다. `inputUnits`가 `["g"]`뿐이면 g만 고른다.
- 단위를 바꾸면 입력한 숫자도 `unitGrams`로 환산한다.

사용자가 고른 단위는 결과 화면까지 유지한다.

## 기본 양념

- 기본 양념은 있다고 보고 계산한다는 한 줄 안내를 둔다.
- 안내 옆에 목록을 펼치는 버튼을 둔다. 기본은 접힘이다. 키보드로 열 수 있고 `aria-expanded`를 쓴다.
- 목록은 `pantry`가 `"기본"`인 재료에서 가져온다. 개수와 이름을 코드에 쓰지 않는다. 읽기 전용이다.

## 인분

- "요리 하나의 인분"을 고르는 인라인 선택기다. 값은 1~4인분, 기본은 2인분이다.
- 결과에서 돌아와도 고른 값을 유지한다.

## 주 행동

- 화면 아래 고정 버튼으로 둔다.
- 재료가 없으면 비활성이고 이유를 근처 문구로 알린다.
- 양을 정하지 않은 재료가 있으면 남은 개수를 알려 준다. 누르면 첫 미완료 재료를 펼친다.
- 모든 재료의 양을 정하면 요리 찾기로 바뀐다. 누르면 계산 중 화면으로 간다.

## 확인 기준

- 재료 여러 개를 고르고, 시트를 닫아도 목록이 바뀌지 않는다.
- 검색으로 재료를 가린 뒤에도 고른 상태가 유지된다.
- "간장"(기본), "다진마늘"(특수)을 검색하면 "목록에 없어요" 대신 종류별 안내가 나오고 이름은 표준명이다.
- 일반 재료와 양념이 함께 맞는 검색에서는 재료만 보인다.
- "불고기"처럼 양념 별칭의 요리 이름만 맞는 검색은 "목록에 없어요"를 보여 준다.
- 빠른 수량 버튼을 누르면 다음 재료로 이동한다.
- 단위를 바꾸면 숫자가 환산되고, 다시 바꿔도 같은 양을 가리킨다.
- 범위를 벗어난 값에서 오류가 보이고, 입력칸과 설명이 연결돼 있다.
- 실제 휴대폰에서 키보드가 열려도 입력칸과 저장 버튼이 가려지지 않는다.
- 긴 재료 목록에서도 담기 버튼에 닿을 수 있다.
- 결과에서 돌아오면 재료, 양, 단위, 인분이 그대로다.
