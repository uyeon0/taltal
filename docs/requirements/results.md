# 추천 결과

계산 중 화면, 추천 결과, 사용량 시트, 추천 없음과 오류의 요구사항을 정한다. 결과는 레시피 목록이 아니라 재료를 나눠 쓰는 요리 묶음 하나로 읽혀야 한다.

결과 구성은 `docs/wireframes/recipe-results-wireframe.html`을, 화면 사이의 상태 전달은 `docs/wireframes/integrated-flow-wireframe.html`을 참고한다. 데이터와 함수는 `docs/data-contract.md`를, 문구는 `docs/copy.md`를 따른다.

## 계산

- 요리 찾기를 누르면 서버에서 후보를 받고(`POST /api/candidates`), 브라우저에서 `recommend`를 돌린다.
- 사지 않는 묶음(`maxPurchases: 0`)과 조금 사는 묶음(기본값)을 각각 3, 4, 5가지로 계산한다. 두 묶음은 같은 후보를 쓴다.
- 계산이 끝나기 전에 같은 요청을 다시 보내지 않는다. 늦게 도착한 이전 응답이 새 결과를 덮어쓰지 않는다.
- 계산은 화면 입력을 멈추게 하지 않아야 한다.

## 계산 중

- 다람쥐(`mascot.thinking`)와 스피너, 바뀌는 문구를 보여 준다. 문구 규칙은 `docs/design.md`의 "컴포넌트 상태"를 따른다.
- 사용자가 넣은 재료 이름을 넣은 문구를 섞는다.

## 결과 화면 구성

위에서 아래로 다음 순서로 둔다.

| 순서 | 구성 |
| --- | --- |
| 1 | 재료 수정으로 돌아가는 버튼 |
| 2 | 제목, 다람쥐(`mascot.meal`), 각 요리 인분 |
| 3 | 가짓수 라벨과 3·4·5가지 탭 |
| 4 | 요약: 다 쓰는 재료, 남는 재료, 재료별 사용량 버튼 |
| 5 | 요리 카드 목록 |
| 6 | 조금 사는 묶음 제안 |
| 7 | 양 추정 안내 |

- 처음에는 사지 않는 묶음을 보여 준다.
- 인분은 제목 아래에 읽을 수 있는 크기로 쓴다.

## 가짓수 탭

- 탭에는 "N가지"만 쓴다.
- 가짓수가 더 많은데 남는 비율이 줄지 않는 결과는 탭에서 뺀다. 규칙은 `docs/data-contract.md`의 "3·4·5가지 비교"를 따른다.
- `partial`이면 따로 안내하지 않는다. 찾은 가짓수의 탭만 남는다. 예를 들어 5가지를 요청해 4가지만 찾으면 4가지 탭 하나만 남는다.
- 처음 선택되는 탭은 남은 탭 중 가짓수가 가장 많은 것이다.
- 탭은 방향키, Home, End로 옮길 수 있다.
- 탭을 바꾸면 요약, 요리 카드, 사용량 시트가 그 결과로 바뀐다. 바뀐 내용은 탭 가까이에서 알아볼 수 있어야 한다.

## 요약

- 재료 단위로 쓴다. "다 써요 N개"와 재료 이름, "남아요 N개"와 재료 이름과 남는 양을 보여 준다.
- 1g 아래로 남은 재료는 다 쓴 것으로 센다.
- 양은 사용자가 입력한 단위로 `formatAmount`를 써서 보여 준다.
- `leftoverRatio`는 화면에 쓰지 않는다.
- "재료별 사용량 보기"를 누르면 사용량 시트를 연다.

## 요리 카드

- 카드는 `meals` 배열 순서가 아니라 `day` 오름차순으로 보여 준다. 탭이나 묶음이 바뀌면 그 결과의 `day`로 다시 정렬한다.
- 카드를 고를 수 있는 후보처럼 보이게 하지 않는다. 같은 묶음의 요리라는 점이 드러나야 한다.
- 카드를 누르면 레시피 상세 시트를 연다.

카드에는 다음을 보여 준다.

| 항목 | 내용 |
| --- | --- |
| 순서 | "N번째 요리". 번호와 배분색은 `day`를 따른다 |
| 순서 이유 | `urgency`가 "빨리 상함"일 때만 `urgentIngredients`의 이름으로 쓴다. 그 밖에는 번호만 쓴다 |
| 이름, 조리 시간 | `Meal.name`, `Recipe.cookingTime` |
| 이 요리에 쓰는 가진 재료와 양 | `Meal.uses`. 사용자가 입력한 단위로 쓴다 |
| 사야 하는 재료 | `Meal.toBuy`. 다른 재료와 구분해 눈에 띄게 쓴다 |
| 있으면 좋은 재료 | `shoppingList`에서 `optional`인 재료 |
| 필요한 특수 양념 | `Meal.pantryNeeded` |

- 레시피 데이터에 요리 사진이 없으므로 요리 이미지는 두지 않는다. 대신 이 요리에 쓰는 가진 재료의 그림을 작게 나란히 보여 준다. 이름이 옆에 있으므로 그림의 대체 텍스트는 비운다.
- 순서는 추천이다. 지켜야 한다는 뜻의 문구를 쓰지 않는다. 날짜나 요일도 쓰지 않는다.
- 요리마다 "여기까지 하면 남는 양"은 보여 주지 않는다. 사용자가 순서대로 요리하지 않을 수 있어서 오해를 준다.

### 사야 하는 양

- 사야 하는 재료는 입력 단위가 없으므로 재료의 기본 단위(`inputUnits[0]`)로 `formatAmount`를 쓰고 g을 함께 쓴다.
- 있으면 좋은 재료는 양을 쓰지 않고 사는 재료 수에 세지 않는다.
- 구매 단위("대파 1단")로 바꾸지 않는다.

## 조금 사는 묶음

- 사지 않는 묶음을 볼 때 요리 목록 아래에 제안 카드를 둔다. 설명과 버튼 하나로 구성하고, 전후 비교표는 두지 않는다.
- 버튼을 누르면 조금 사는 묶음으로 바뀌고 제목도 바뀐다. 다시 사지 않는 묶음으로 돌아갈 수 있다.
- 사지 않는 묶음이 `empty`이면 조금 사는 묶음을 바로 보여 주고, 그 이유를 위에 안내한다.

## 사용량 시트

- 재료마다 누적 막대와 펼침 내역을 보여 준다. 표현은 `docs/design.md`의 "재료 배분 표현"을 따른다.
- 남는 양이 큰 재료부터 놓고, 다 쓴 재료는 맨 뒤에 둔다.
- 요리별 색, 번호, 이름은 요리 카드와 같다.
- 막대 비율은 g 내부값으로 구하고, 양 표시는 입력 단위로 한다.
- 표시한 부분의 합이 전체와 다르면 합계 안내를 붙일 수 있다.
- 사야 하는 재료와 양념은 막대에 넣지 않는다.

## 추천 없음과 오류

| 상태 | 화면 |
| --- | --- |
| 두 묶음 모두 `empty` | 다람쥐(`mascot.retry`), 추천 없음 안내, 재료 수정 버튼 |
| 서버 오류 | 다람쥐(`mascot.retry`), 오류 안내, 다시 찾기 버튼과 재료 수정 버튼 |

- 두 상태 모두 입력한 재료와 인분은 유지된다.
- 다시 찾기는 같은 재료와 인분으로 다시 계산한다.

## 확인 기준

- 결과에서 재료 수정으로 갔다 돌아오면 재료, 양, 단위, 인분이 그대로다.
- 요리 카드의 번호, 사용량 시트의 번호와 색이 같은 `day`를 따른다.
- 가짓수가 늘어도 남는 비율이 줄지 않는 결과가 탭에 없다.
- 작은 양이 0으로 보이지 않는다. 1g 이상 남은 재료를 "다 써요"로 쓰지 않는다.
- 뒤쪽 요리 카드를 열고 닫아도 원래 위치와 포커스로 돌아온다.
- 응답이 느리거나 실패해도 화면이 멈추지 않고, 버튼을 여러 번 눌러도 결과가 한 번만 반영된다.
