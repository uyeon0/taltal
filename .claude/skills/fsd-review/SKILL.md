# FSD 구조 점검

폴더 구조와 모듈 간 의존 관계를 FSD 기준으로 점검하고 구조적 판단만 제공한다.

- 코드를 고치지 않는다.
- 코드 수정안(diff, 구현 코드, 파일별 수정 절차)을 제시하지 않는다.
- 모든 판단에 근거가 된 파일 경로와 import 문을 붙인다. 코드에서 확인하지 못한 내용은 추측이라고 밝힌다.

## 레이어 규칙

위에서 아래 순서로 의존한다. 모듈은 자기보다 아래 레이어만 import한다.

```
app → pages → widgets → features → entities → shared
```

- `app`과 `shared`를 뺀 레이어는 슬라이스로 나뉜다. 같은 레이어의 다른 슬라이스를 import하지 않는다.
- `app`과 `shared`는 슬라이스 없이 세그먼트로 나뉘므로 내부 import를 허용한다.
- 슬라이스 밖에서는 슬라이스의 public API(`index.ts` 등)로만 접근한다.

## 분석 순서

### 1. 레이어 매핑

- 대상 폴더를 `app/pages/widgets/features/entities/shared`로 매핑해 표로 정리한다.
- 폴더 이름이 레이어와 다르면(예: 프레임워크 라우팅과 충돌을 피한 `_app`, `_pages`) 실제 역할로 매핑하고 그 근거를 적는다.
- 프레임워크의 라우팅 폴더처럼 레이어 밖에 있는 폴더는 따로 표시한다. 레이어 어디에도 넣을 수 없는 폴더도 빠뜨리지 않고 적는다.
- 경로 alias는 `tsconfig` 등의 설정에서 확인한다. import 분석은 alias와 상대 경로를 모두 포함한다.

### 2. import 방향

- 아래 레이어가 위 레이어를 import하는 경우를 찾는다.
- 값 import와 타입 전용 import를 구분해 적는다.
- `shared`처럼 슬라이스가 없는 레이어를 제외하고, public API를 우회한 import도 함께 적는다.

### 3. feature 간 직접 의존

- 한 feature가 다른 feature를 import하는 경우를 찾는다.
- 두 feature가 왜 연결되어 있는지 적는다. 공유하는 것이 데이터인지, 사용자 동작의 순서인지 구분한다.
- `entities`, `widgets`의 같은 레이어 교차 import도 함께 적는다.

### 4. entities의 상위 레이어 침범

- `entities`가 `features` 이상을 import하는 경우를 찾는다.
- import가 없어도 책임이 넘어온 경우를 본다. 사용자 동작의 시나리오나 특정 화면 전용 분기가 entity 안에 있는지 확인한다.
- entity의 도메인을 표현하는 UI는 위반이 아니다. UI 자체가 아니라 그 UI가 맡은 책임으로 판단한다.

### 5. shared의 비즈니스 로직 포함 여부

- `shared`가 다른 레이어를 import하는 경우를 찾는다.
- import가 없어도 특정 도메인의 이름, 타입, 규칙이 들어 있는지 확인한다.
- 프로젝트 전체가 쓰는 인프라(API 클라이언트, 공통 에러 타입 등)는 비즈니스 로직으로 보지 않는다.

### 6. 순환 의존과 응집도·결합도

- 슬라이스 간, 모듈 간 순환 의존을 찾는다. 도구로 확인할 수 있으면 검사하고, 사용한 방법을 적는다.
- 한 슬라이스의 변경이 여러 슬라이스의 변경으로 번지는 결합을 찾는다.
- 한 도메인이 여러 슬라이스에 흩어져 있거나, 한 슬라이스에 무관한 책임이 모여 있는 곳을 찾는다.

## 출력 형식

1. 레이어 매핑 표
2. 점검 결과 요약: 2~6단계마다 "위반 있음 / 없음 / 판단 필요"와 건수
3. 리스크 목록: 항목마다 아래 형식으로 적고, 심각한 순서로 나열한다.

```
#### <리스크 이름>

- 근거: 파일 경로와 import 문
- 현재 문제: 지금 발생하는 문제. 없으면 "없음"
- 확장 시 문제: 어떤 변경이 들어올 때 어떤 문제가 생기는지
- 대안: 구조 수준의 방향과 그 비용
```

- 대안은 의존 방향이나 책임 위치를 어떻게 바꿀 수 있는지까지만 적는다.
- 규칙 위반이어도 현재 문제와 확장 시 문제가 모두 약하면 그렇게 적는다. 위반 건수를 늘리려고 리스크를 부풀리지 않는다.
- 위반을 찾지 못했으면 찾지 못했다고 적고, 어떤 범위를 어떻게 확인했는지 적는다.
